# 拾刻 Snapday v2｜项目说明

## 目标与范围

将活动海报、群通知截图整理为用户确认过的日程，支持多项活动集中管理与日历导出。v2 在本地体验之上提供账号、服务端持久化及多设备访问。

核心流程为：**截图输入 → 本地 OCR → 日期解析 → 人工核对 → 保存到当前空间 → 导出日历**。活动较多时，逐张处理的结果可以累计到同一条时间线。节省重复录入是产品目标，尚无耗时收益对照测量。

每张图处理一个主活动与一个可选截止事项。原文和可编辑卡片并排核对；字段缺失时交由用户补充。复杂课表、重复日程、多活动长图和通用语义理解不在当前范围。

## 架构

```text
浏览器
  图片 → Tesseract.js Worker / WASM → 识别原文
       → 中文日期规则 → 草稿确认
       ├─ 游客空间：localStorage → .ics
       └─ 账号空间：同源 API 客户端
                         ↓
Node HTTP + Fetch REST API
  Cookie 会话 → 账号隔离 → 字段与版本校验
                         ↓
SQLite：users / sessions / events / auth_attempts
                         ↓
后端 iCalendar 生成与下载
```

前端使用原生 ES Modules。OCR 引擎、Worker、WASM 和中英字库由站点同源提供，识别在浏览器完成；粘贴文字可直接进入日期解析，绕过图片识别。

`server/api.mjs` 使用 Fetch Request / Response，数据库依赖为 D1 形状的 `prepare().bind()`、`first()`、`all()`、`run()` 和 `batch()` 接口。`server/sqlite.mjs` 以 Node 内置 SQLite 实现这些操作；`server/node.mjs` 提供 HTTP 和静态资源服务。表结构由初始化过程建立，API 请求不执行建表操作。

D1 形状接口提供运行时适配边界。独立云端部署还需要平台路由、数据库绑定和迁移配置；本仓库的可运行全栈入口为 Node / SQLite。

## 两种数据空间

| 行为 | 游客空间 | 账号空间 |
| --- | --- | --- |
| 保存 | 当前浏览器 localStorage | 后端 SQLite，按账号归属保存 |
| 刷新页面 | 恢复该站点的本地事项 | 有效会话恢复后读取账号事项 |
| 其他设备 | 不自动迁移本地存储 | 同后端、同账号，手动刷新读取修改 |
| 导出 | 浏览器生成 .ics | 后端从当前账号生成 .ics |
| 退出账号 | 恢复本地事项 | 服务端退出当前会话，日程继续保留 |

登录不自动合并或上传游客数据。用户显式执行「导入本地日程」后，前端按数量与请求体大小拆分批次，服务端先校验完整批次，再以事务写入，并按账号内的指纹约束跳过重复项。

**事务范围是单次请求。** 多批次导入中断时，先前成功的批次保留；原本地记录也保留，可刷新核对后重试。

原图不上传、不写入日程数据库。登录后保存或导入的标题、时间、地点、备注、原文依据及来源名称会发送至后端。数据库不是端到端加密存储，部署方可通过数据库管理访问这些内容。

## 账号与会话

- 用户名为 3–32 位英文字母、数字、下划线或短横线，服务端统一为小写；显示名称与登录名分开存储。
- 密码为 8–128 个字符，使用独立随机盐和 100,000 次 PBKDF2-SHA256 派生后保存，不保存明文密码。
- 会话使用随机令牌；数据库仅保存 SHA256 摘要和 7 天有效期，浏览器通过 HttpOnly、SameSite=Lax Cookie 携带令牌。HTTPS 来源下增加 Secure 属性。
- 写入接口要求同源 Origin（或同源 Referer）及 JSON 请求体；认证限流计数存储在数据库中。
- `X-Snapday-Account` 用于检测其他标签页切换账号后的请求不一致，Cookie 会话仍是唯一授权依据。
- 当前没有邮箱验证、密码找回、第三方登录或账号管理后台。

具体接口和错误响应见 [API.md](API.md)。公网部署的 HTTPS 来源和持久存储要求见 [DEPLOY.md](DEPLOY.md)。

## 日程规则与一致性

- 按 `Asia/Shanghai` 解释输入，导出时转换为 UTC。缺年份、相对日期或模糊时段均提示核对，未确认草稿不能保存至后端。
- 活动结束时间必须晚于开始时间；缺失时不填充默认时长，也不参与精确时段冲突检查。相邻衔接的区间不算重叠，截止事项不视为持续活动。
- 重复指纹由规范化标题、类型、日期、起止时间及地点生成。数据库约束以账号为单位，账号之间的相同事项不互相影响。
- 后端更新与删除必须携带当前 `version`；旧版本返回 `409 VERSION_CONFLICT`，避免覆盖其他页面已经保存的修改。
- 事件身份由服务端生成，包含稳定 ID、版本及创建/更新时间；账号日历导出以服务端的当前记录为准。
- 同一后端的其他设备修改需手动刷新读取；当前不提供实时推送、自动合并冲突或离线写入队列。

日历输出包括 `VCALENDAR` / `VEVENT`、稳定 UID、UTC 时间、文本转义、CRLF 换行、UTF-8 折行及可选 `VALARM`。文件需要手动导入日历软件，后续网页修改不会自动同步至已导入事件。

## 验收范围

| 场景 | 核对目标 |
| --- | --- |
| 图片识别 | OCR 原文来自当前图片，卡片由本次原文解析生成 |
| 人工确认 | 可修改错字、补充缺失字段，确认后保存 |
| 本地空间 | 刷新恢复、编辑删除、导出及原文依据保留 |
| 账号与持久化 | 注册登录、会话恢复、服务重启后数据保留、账号隔离 |
| 写入一致性 | 重复约束、旧版本冲突、账号切换检查、批次事务 |
| 多设备读取 | 同一后端同一账号，手动刷新后读取已保存修改 |
| 日历导出 | 当前空间的标题、地点和时间正确，中文与格式可解析 |

上述是功能与验收范围，不表示每项都完成真实浏览器或外部日历客户端验证。已执行结果和待测项目统一记录在 [QA.md](QA.md)。
