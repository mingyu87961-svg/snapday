# 拾刻 Snapday

**把截图里的重要时刻，交给日历。**

Snapday 是一个面向活动通知、群聊截图和报名海报的个人日程工具。上传图片后，在浏览器内识别文字、整理活动和截止时间；核对后保存到时间线，并导出可以导入日历的 `.ics` 文件。

**多项活动集中整理，省下重复录入的时间。** 当课程、讲座、社团活动和报名通知较多时，可以逐张识别截图、核对并保存，把不同活动汇总到同一条时间线，再一次性导出到日历。通过 OCR 预填信息，减少反复翻找截图、抄写日期地点和逐条新建日历事项的操作，让活动较多时的日程整理更省时。

## 能帮你节省哪些操作

- **多项活动统一管理**：将多张截图中的活动逐次保存到同一条时间线，集中查看、搜索和筛选，减少在相册与群聊之间来回查找。
- **减少重复手工录入**：OCR 识别文字并提取时间候选，用户对照原文核对、修正，减少从头抄录标题、日期和地点的步骤。
- **一次导出多项日程**：核对并保存多项活动后统一导出 `.ics`，再导入日历，减少逐条创建事件的操作。

当前流程为逐张识别、逐项核对、累计保存与统一导出。实际节省时间取决于截图数量、清晰度和人工修正量，尚未进行耗时对照测量。

## 功能

- **截图输入**：选择图片、拖放或粘贴，支持 PNG / JPG / WebP；也可以直接粘贴通知文字。
- **活动拆分**：从一则通知提取一个主活动及一个可选截止事项，保留原文依据。
- **日期核对**：支持常见中文日期、相对日期和时间区间；缺失字段与含糊日期需要人工确认。
- **日程管理**：多项活动集中保存在当前浏览器，支持搜索、筛选、编辑、移除与撤销。
- **重复与冲突检查**：拦截重复事项；对有明确起止时间的活动检查时段重叠。
- **日历导出**：支持逐项或批量导出，保留标题、地点、时间和可选提醒。

## 快速运行

需要 **Node.js 20 或更新版本**。应用没有 npm 运行依赖，无需安装依赖即可启动。

下载或克隆仓库后，在项目目录运行：

```sh
npm start
```

打开 **http://127.0.0.1:4173**。Windows 也可以运行 `scripts/start-local.cmd`；终端按 `Ctrl+C` 停止服务。

应用需要 HTTP 服务提供 Worker、WASM 和 ES Modules，不能直接双击 `index.html` 启动。

## 快速体验

1. 点击「摄影分享会」加载自制样例图片，再点击「识别并整理日程」。
2. 对照原图，修改识别错字并核对活动时间、地点和报名截止。
3. 勾选确认并保存，在下方时间线查看、搜索或修改事项。
4. 继续上传其他截图并核对保存，将多项活动汇总到同一条时间线。
5. 点击「导出全部日程」，将下载的 `.ics` 文件一次性导入自己的日历软件。

内置样例通过真实 OCR 流程处理，选择图片不会预填识别结果。第一次运行需要加载本仓库提供的字库和引擎；OCR 仍可能出现错字或遗漏。

## 技术实现

```text
截图 / 通知文字
    ↓
Tesseract.js 本地 OCR
    ↓
中文日期解析与字段校验
    ↓
可编辑草稿 + 原文核对
    ↓
重复 / 时段冲突检查
    ↓
localStorage 时间线 → RFC 5545 日历文件
```

| 层次 | 实现 |
| --- | --- |
| 页面与交互 | HTML、CSS、原生 JavaScript ES Modules，适配手机和桌面 |
| 图片识字 | Tesseract.js 6.0.1，Web Worker + WASM，中英字库同源自托管 |
| 时间处理 | 确定性日期规则、人工确认、Asia/Shanghai 转 UTC |
| 数据保存 | 当前浏览器的 localStorage |
| 日历导出 | 稳定 UID、中文转义、UTF-8 折行、可选 VALARM |
| 验证 | Node.js 内置测试、静态资源检查、浏览器交互实测 |

**本项目使用 AI 编程工具辅助开发，运行时不调用通用大语言模型 API。** 截图文字由本地 OCR 模型识别，日期整理与校验由 JavaScript 实现，无需 API 密钥。

## 数据与适用范围

- 截图在浏览器内处理，不发送给远程 OCR 或大模型服务；OCR 引擎及字库从站点静态资源加载。
- 已保存的日程与原文依据保存在当前浏览器，原始截图不写入日程存储。清理网站数据会移除记录。
- 首版处理一张图中的一个主活动和一个可选截止事项，不覆盖复杂课表、重复日程或多活动长图。
- 输入按中国标准时间（UTC+08:00）解释；所有草稿都需要人工确认，OCR 错字可直接修改。
- 没有结束时间的事项可以导出，但不会参与精确时间冲突检查。
- 导出文件需手动导入日历。提醒由日历软件按自身设置执行；网页不负责后台推送，也不会自动同步后续修改。

## 项目结构

```text
dist/
  index.html            页面与空态
  styles.css            响应式界面
  app.mjs               OCR、编辑、保存和时间线交互
  lib/engine.mjs        日期提取、校验、去重、冲突与日历序列化
  assets/               自制通知海报
  vendor/               固定版本 OCR 引擎、WASM、字库与许可证
scripts/                本地服务和资源检查
tests/                  自动化测试
docs/
  PROJECT.md            用户故事与需求范围
  QA.md                 实际验收记录及限制
  DEPLOY.md             静态部署说明
.github/workflows/      自动检查与手动 Pages 发布
```

## 部署

整个 `dist/` 目录可以部署到静态托管服务。GitHub Pages 部署步骤见 [部署说明](docs/DEPLOY.md)，页面和 OCR 资源支持仓库子路径，不依赖原有私有托管平台的登录。
