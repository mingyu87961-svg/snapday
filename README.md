# 拾刻 Snapday · v3 AI 日程整理

**把截图里的重要时刻，交给日历。**

Snapday 是一个面向活动通知、群聊截图和报名海报的个人日程工具。在浏览器内识别截图文字，使用本地规则或 DeepSeek 理解通知，核对后保存到时间线，再统一导出日历文件。v3 增加了服务端 AI 多活动整理，保留账号日程和免登录本地体验。

**多项活动集中整理，减少重复录入。** 当课程、讲座、社团活动和报名通知较多时，可以逐张识别截图，也可以让 AI 将一段通知中的多个活动与截止事项拆成草稿；核对后的事项累计到同一条时间线，再统一导入日历，减少反复翻找通知、抄写字段和逐条建日程的步骤。实际节省时间取决于输入质量和人工修正量，尚未进行耗时对照测量。

## 功能

- **截图与文字输入**：选择、拖放或粘贴 PNG / JPG / WebP 图片，也支持粘贴通知文字。
- **本地识别与日期核对**：「仅提取文字」只运行浏览器 OCR，不生成草稿；「识别并整理日程」继续使用本地规则，整理一个主活动及一个可选截止事项。
- **DeepSeek 多活动整理**：登录并同意本次发送通知文字后，经服务端模型接口生成最多 20 个活动或截止草稿，展示原文依据与待确认提示；不会自动保存。
- **日程管理**：时间线、搜索、筛选、编辑、移除与撤销，以及重复提示和完整时段冲突检查。
- **账号与云端日程**：用户名注册、登录、退出；已登录事项保存在所连接后端的 SQLite 数据库，按账号隔离。
- **本地数据导入**：登录不会自动上传游客数据，可显式分批导入本地日程，跳过重复项并保留原本地记录。
- **日历导出**：游客模式在浏览器生成文件；账号模式由后端从该账号数据生成，支持单项与全部日程导出。
- **多设备访问**：不同设备连接同一个可访问的后端，登录同一账号后手动刷新日程，读取已保存的修改。

## 快速运行

需要 **Node.js 22.13 或更新版本，推荐 Node.js 24**。本仓库没有 npm 运行依赖，**无需 `npm install`**。

在项目目录运行：

```sh
npm start
```

打开 **http://127.0.0.1:4173**。服务同时提供前端页面与 `/api/` 接口，首次启动自动创建 `data/snapday.sqlite`，再次启动保留账号和日程。Windows 也可运行 `scripts/start-local.cmd`；终端按 `Ctrl+C` 停止服务。

### 启用 DeepSeek

将 `.env.example` 复制为 `.env`，在本机编辑并配置：

```dotenv
DEEPSEEK_API_KEY=填写你自己的服务端密钥
DEEPSEEK_MODEL=deepseek-flash
```

`npm start` 自动读取 `.env`；配置后重启服务。真实密钥只保存在服务端环境中，`.env` 已被 Git 忽略。未配置密钥时，账号与本地整理仍可使用，AI 接口返回未配置状态，不会以本地规则结果冒充 AI。

网页中的 AI 状态表示服务端是否提供了配置，不代表密钥、额度或网络已通过真实调用验证。部署配置和 Docker 环境变量见 [DEPLOY.md](docs/DEPLOY.md)。

只体验静态前端时：

```sh
npm run start:static
```

静态模式仍使用 http://127.0.0.1:4173，仅支持游客本地功能。两个启动命令不要同时占用同一端口。应用依赖 HTTP 服务加载 Worker、WASM 与 ES Modules，不支持双击 HTML 启动。

## 快速体验

1. 点击「摄影分享会」加载自制样例，再点击「识别并整理日程」执行 OCR。
2. 对照原图修正错字，核对活动时间、地点和报名截止。
3. 确认保存后继续处理其他截图，把多项活动汇总到时间线。
4. 在全栈服务中注册或登录，按需点击「导入本地日程」；本地与账号日程分别保留。
5. 点击「导出全部日程」，将 `.ics` 文件手动导入自己的日历软件。

使用 AI 时，可在放入截图后点击「仅提取文字」，检查 OCR 原文，再登录并在「通知文字与 AI 整理」中设置参考日期、勾选本次发送同意项，点击「AI 理解并整理」。也可以直接粘贴多活动通知。仅提取文字不会发送 AI 请求或生成本地规则草稿；已有草稿需先保存或舍弃，避免覆盖修改。

AI 结果先进入待核对区，逐项确认后才写入日程。失败、取消或超时不会自动重试或切换成本地结果；本地规则仍可由用户单独点击使用。

第一次识别需要加载本站的字库和引擎。内置样例来自实际图片识别，选择样例不会预填结果；OCR 仍可能产生错字和遗漏。

## 数据如何保存

| 模式 | 保存位置 | 其他设备如何访问 |
| --- | --- | --- |
| 游客本地体验 | 当前浏览器的 localStorage | 不自动跨设备；清理网站数据会移除记录 |
| 登录账号 | 当前后端的 SQLite 数据库 | 连接同一后端并登录同一账号，手动刷新日程 |

原始图片始终在浏览器中识别，不上传到后端或 DeepSeek。**使用 AI 时，当前通知文字、参考日期和时区上下文会经过后端发送给 DeepSeek。** 不会自动附带其他已保存日程；若通知文字包含个人信息，这些文字也属于本次发送内容。

AI 调用历史仅保存模型、提示词版本、状态、错误码、输入字数、事项数量、token 用量和耗时等元数据，不保存完整通知或模型原始输出。**账号模式确认保存的日程字段、备注和原文依据会存入后端数据库。** 已保存游客日程只有在显式导入时才上传；退出账号恢复游客时间线，不删除账号日程。

导入按批次提交。单个批次使用数据库事务；若中途失败，已成功的批次可能保留。界面显示已确认进度，刷新后可重试，重复事项会跳过。

## 技术架构

```text
截图 / 通知文字
    → 浏览器 Tesseract.js OCR
    ├─ 本地规则解析
    └─ 用户同意 + 登录 → 服务端 DeepSeek JSON mode
                       → 结构校验 + 原文依据匹配
    → 可编辑草稿 + 人工确认
    ├─ 游客：localStorage → 浏览器生成 .ics
    └─ 账号：同源 REST API → SQLite → 后端生成 .ics
```

| 层次 | 实现 |
| --- | --- |
| 前端 | HTML、CSS、JavaScript ES Modules、Web Worker、WASM |
| OCR | Tesseract.js 6.0.1，中英字库同源自托管 |
| AI 理解 | 仅服务端调用 DeepSeek 固定接口，默认 `deepseek-flash`，JSON mode、受控输出与原文依据匹配 |
| API | Fetch Request / Response 接口，Node 内置 HTTP 服务承载 |
| 存储 | Node 内置 SQLite，参数化查询、外键约束、事务、按用户隔离 |
| 认证 | 随机盐 PBKDF2-SHA256 密码哈希、Cookie 会话、数据库保存会话令牌摘要 |
| 一致性 | 账号一致性检查、事项版本校验、重复约束、分批事务导入 |
| AI 可观测性 | 状态接口、账号隔离的最近调用元数据、数据库限流 |
| 日历 | RFC 5545、上海时间转 UTC、稳定 UID、UTF-8 折行、可选 VALARM |
| 部署 | Node / Docker；静态游客前端可单独部署到 GitHub Pages |

项目同时包含本地规则与真实模型调用两条路径。DeepSeek 密钥和模型选择只由服务端配置，浏览器不能指定任意上游地址。原文依据匹配仅确认引用片段可定位，不保证 AI 对每个字段的理解正确，仍需人工核对。架构见 [项目说明](docs/PROJECT.md)，接口见 [API 文档](docs/API.md)。

## 适用范围

- 本地规则每次提取一个主活动及一个可选截止事项；AI 路径单次输入最多 12000 字符，最多返回 20 个草稿。复杂课表、重复日程及低质量 OCR 仍需要人工整理。
- AI 需有效账号、服务端密钥和本次明确同意；失败不会自动换用本地规则。取消主要停止接收结果，不保证已经发出的上游请求不会产生费用。
- 输入按中国标准时间（UTC+08:00）解释；所有草稿需要人工确认。没有结束时间的活动不参与精确时段冲突检查。
- 账号使用用户名与密码，没有邮箱验证、密码找回或第三方登录。
- 多设备数据依赖同一个后端。当前没有实时推送、自动刷新或离线云端写入队列。
- `.ics` 是导出快照，网页后续修改不会自动同步到系统日历；提醒由导入的日历软件执行。
- 静态托管只提供游客体验，不能运行账号服务或数据库。全栈部署需持久化数据库并正确配置 HTTPS 来源。

```text

  app.mjs                OCR、账号模式、草稿与时间线

  assets/                自制样例海报
  vendor/                OCR 引擎、WASM、字库及许可证

  node.mjs               HTTP 与静态资源入口
  api.mjs                Fetch REST API 与认证逻辑
  ai.mjs                 DeepSeek 请求、输出校验和证据匹配
  sqlite.mjs             SQLite / D1 形状接口适配
```

## 部署

完整账号功能使用 Node 或 Docker 部署，详见 [部署说明](docs/DEPLOY.md)。GitHub Pages 仅部署 `dist/`，保留截图识别与本地游客体验，不提供账号或服务端存储。

API 使用 D1 形状的数据库接口，便于复用到其他运行时。当前仓库的可复现全栈运行入口为 Node / SQLite；云端运行时需单独绑定数据库与服务端 Secret，历史部署验证及当前版本状态以 QA 记录为准。
